# 电赛信号题方案架构决策手册

> 目的：把题目文字转化为可实现、可回退、可验证的系统架构。  
> 使用顺序：先执行 [`新题启动SOP.md`](新题启动SOP.md) 的需求和预算步骤，再用本手册选架构，最后填写 [`../templates/solution_architecture_template.md`](../templates/solution_architecture_template.md)。  
> 边界：本手册提供决策规则，不替代数据手册、CubeMX、板级计算或实测。

## 1. 方案输出必须回答什么

完整方案不是器件列表。最终必须回答：

1. 输入和输出分别是什么物理量；
2. 信号从哪里产生、经过哪些模拟环节、在哪里测量；
3. 每一级的频率、幅度、阻抗、动态范围和误差；
4. 哪些功能由硬件完成，哪些由 MCU 软件完成；
5. 采样、更新、计算和控制的时间基准；
6. 使用哪些 Knowledge、Library 和板级 adapter；
7. 正常、超时、故障、人工换线和回退时如何运行；
8. 如何逐级证明基础要求和发挥要求。

缺少任一项时，方案仍是候选，不得直接进入大规模编码。

## 2. 第一次分类：题目到底要求什么能力

一题可以同时命中多类。

| 能力类 | 典型动词 | 主要输出 | 核心风险 |
|---|---|---|---|
| G 信号生成 | 产生、输出、调制、合成、移相 | 频率、幅度、波形、相位 | 更新率、DAC/DDS 带宽、负载、杂散 |
| M 信号测量 | 测量、显示、计算、判定 | Vpp、RMS、频率、相位、失真 | Nyquist、量程、标定、稳定时间 |
| C 特性测量 | 扫频、幅频、相频、传递函数 | 频率响应、模型参数 | 激励稳定、参考通道、换线、比值误差 |
| I 识别分类 | 判断、识别、区分、估计 | 类型、参数、置信度 | 特征不足、阈值过拟合、未覆盖样本 |
| L 闭环控制 | 自动调节、稳定、校准、跟踪 | 目标误差内稳定输出 | 饱和、噪声底、振荡、超时 |
| A 自动流程 | 一键、无人干预、规定时间完成 | 完整状态和结果 | 阻塞、恢复、错误不可观察 |

架构图必须给每个题目验收项分配至少一个能力类和一个验证方法。

## 3. 第二次分类：四个硬约束

### 3.1 频率约束

先计算：

```text
每通道有效采样率 fs_effective
Nyquist = fs_effective / 2
每周期点数 = fs_effective / f_signal
FFT 分辨率 = fs_effective / N
```

决策：

| 条件 | 允许方案 | 禁止结论 |
|---|---|---|
| `f_signal < Nyquist` 且每周期点数足够 | ADC 波形、Vpp、RMS、FFT | 仍需检查前端带宽和采样抖动 |
| 接近 Nyquist | 只做经证明的窄带/混叠受控方案，或降低频率 | 不能因“ADC 标称高速”就宣称可测 |
| 超过 Nyquist，但只需幅值 | RMS/检波器转慢变量，或模拟降频 | 不能直接用欠采样波形算 Vpp/FFT |
| 超过 Nyquist，需频率 | 比较器 + 定时器输入捕获，或分频 | 不能用低速 ADC 频谱猜测 |
| 超过 Nyquist，需相位/波形 | 模拟混频/下变频、高速前端或外部方案 | RMS 芯片不能提供相位 |
| STM32 采样率不足，但需要一段高速原始波形 | FPGA + 并行 ADC 采集冻结窗口，再经校验帧送 STM32 | 必须同时预算 ADC Nyquist、窗口时长和主控链路吞吐；窗口方案不等于连续流 |

关联 Knowledge：`K-MEAS-001`、`K-MEAS-002`、`K-STM32-001`。

### 3.2 幅度和阻抗约束

逐级填写：

```text
源开路电压
→ 源阻抗/端接后的实际电压
→ 增益/衰减
→ 偏置
→ ADC/DAC/运放安全范围
```

否决条件：

- 任何一级可能超供电轨、ADC 绝对最大值或器件输入范围；
- 把高阻示波器读数当作 50 Ω负载电压；
- 没有说明 Vpp、峰值、RMS 的换算条件；
- 可变增益闭环没有安全上下限和饱和检测；
- DAC 直接驱动低阻或大电容却没有带载验证。

关联 Knowledge：`K-STM32-003`、`K-ANALOG-001`、`K-MEAS-003`。

### 3.3 时间约束

总时间至少包括：

```text
切换/继电器
+ 模拟建立
+ RMS/滤波稳定
+ 采样窗口
+ 计算
+ 闭环迭代
+ UI/存储
+ 故障重试
```

一键完成题必须有总超时。任何 `while(!done)`、无限等待首点稳定或无上限闭环，都不能进入正式方案。

### 3.4 自动化约束

| 题目条件 | 架构要求 |
|---|---|
| 允许人工换线 | 状态机必须明确提示、确认和安全增益 |
| 按键后禁止人工干预 | 所有切换、测量、判断和回退必须自动完成 |
| 规定时间内完成 | 每个状态有预算和超时，保存最后有效结果 |
| 外部仪器只可用于调试 | 正式测量链不能依赖示波器读数 |

## 4. 信号生成方案

### 4.1 选择矩阵

| 需求 | 首选 | 备选 | 主要验证 |
|---|---|---|---|
| 低频任意波、双通道同步、波形可编程 | STM32 DAC + TIM TRGO + DMA | 外部高速 DAC | 更新率、DMA 同步、负载、重构滤波 |
| 稳定正弦/三角/方波、频率跨度大 | AD9833 等 DDS | MCU DAC LUT | MCLK、频率字、模拟输出幅度、杂散 |
| 只需数字方波/时钟 | 定时器 PWM/输出比较 | DDS 方波 | 频率量化、占空比、边沿和电平 |
| 高频 RF 指标 | 真实 RF DDS/PLL/射频链 | 低频等效仅用于算法阶段 | 载频、功率、匹配、频谱纯度 |

### 4.2 软件分层

```text
题目策略：目标频率/幅度/波形/相位
    ↓
输出服务：Start / Update / Stop / Fault
    ↓
协议或波表模块：AD9833 / dual_signal_generator
    ↓
板级 adapter：GPIO/SPI/DAC/DMA/TIM
```

可用 Library：

- AD9833：L2 fake-bus，仅协议和控制字；
- `dual_signal_generator`：L0；
- `dac_dma_output`：L0，STM32F4 HAL 假设；
- `delay_line`：L0。

没有 L3 模块，因此所有生成链都必须在新题板上重新验证。

## 5. 测量方案

### 5.1 幅值

| 条件 | 方案 |
|---|---|
| 低频、波形未知、采样充分 | ADC `max-min` 测 Vpp；同时检查异常码和削顶 |
| 正弦且采样充分 | ADC 去直流 RMS，可按条件换算 Vpp |
| 高频只需幅值 | AD637/真 RMS/检波器 → 慢变 DC → ADC |
| 幅度跨度大 | 前置衰减/VGA/多量程；切换后重新稳定和标定 |

可用 Library：

- RMS 计算：L2；
- statistics/percentile：L2，可用于稳健统计；
- AD603 模型：L2，但标定数据由项目拥有；
- LUT 插值：L2。

### 5.2 频率

| 输入 | 方案 |
|---|---|
| 已整形成数字边沿 | TIM 输入捕获/DMA + frequency measure core |
| ADC 正弦且采样充分 | FFT 峰值或过零；需要抗噪和窗口 |
| 候选频率有限 | Goertzel/针对性检测，可降低计算量 |

`frequency_measure_core` 为 L2 纯计算模块，不拥有 TIM、DMA、计数器位宽或中断。

### 5.3 相位

相位需要共同时间基准。允许方案：

- 双通道同步 ADC；
- 同一计数器的双输入捕获；
- 已知参考下的同步检波；
- FFT/DFT 相位，但必须保证采样同步、窗口和频点关系。

禁止：

- 用两个非同步单通道采样结果直接相减；
- 用 RMS 芯片输出推相位；
- 未处理计数器回绕和整周期歧义；
- 把示波器人工相位读数当正式自动方案。

## 6. 特性测量与未知电路识别

### 6.1 幅频测量链

```text
设定频率
→ 设定安全激励
→ 等待输出链稳定
→ 测参考 Vin
→ 测被测端 Vout
→ 检查量程/饱和/噪声底
→ 计算 |H(f)| = Vout / Vin
→ 保存条件和质量状态
```

必须明确 Vin/Vout 是同步双通道、自动切换还是人工换线。人工换线原型不能宣称满足一键自动要求。

### 6.2 扫频点选择

分层选择：

1. 快速分类点：低端、高端和必要的中间点；
2. 转折搜索点：对数扫频或自适应细化；
3. 拟合点：覆盖通带、转折和阻带；
4. 验证点：不参与拟合，用于检查泛化。

固定使用“两点法”前必须证明候选类别和频率范围使两点具有区分度。带通/带阻通常至少需要中间点。

### 6.3 模型与分类

可用模块：

- 二阶传递函数：L2，用于给定模型的响应计算；
- LUT 插值：L2，用于实测校准曲线；
- FFT 工具：L2；
- statistics：L2；
- RMS：L2。

新增 experimental 核心：

- `sweep_service` L1：非阻塞频点、重试和总超时；
- `transfer_response` L1：Vin/Vout 质量门、增益/dB 和电平交点；
- `filter_classifier` L1：保守输出 LP/HP/BP/BS/UNKNOWN；
- filter-ID pipeline：上述三者的 build-only fake 组合测试。

当前仍不包含参数搜索/拟合器、实测阈值数据集、置信度模型或硬件切换服务。
因此自动辨识可以复用接口链，但必须在新题保存训练点、验证点、阈值、误差和
失败状态；测试 ELF 未运行，不能按 L2 使用。

## 7. 闭环控制架构

### 7.1 标准状态

```text
SAFE_INIT
→ APPLY
→ SETTLE
→ MEASURE
→ VALIDATE_MEASUREMENT
→ COMPUTE_LIMITED_CORRECTION
→ CONVERGED / RETRY / FAULT
→ SAFE_STOP
```

### 7.2 必需保护

- 控制量上下限；
- 单次修正上下限；
- 输出量和 ADC 量程检查；
- 最小有效读数；
- 饱和/削顶检测；
- 最大迭代次数；
- 单状态和总超时；
- 启动、停止、换线和故障时的安全值；
- 错误码和最后有效结果。

`target/measured` 只能在测量有效、未饱和、单位一致时使用。固定 `[0.7, 1.3]` 等限制是历史经验起点，不是所有系统的通用参数。

## 8. 推荐软件架构

```text
App/
  contest_requirements      题目验收项和模式
  contest_state_machine     正常/超时/回退流程

Services/
  signal_output_service     生成、幅度和安全停机
  measurement_service       采样、稳定、质量和结果
  sweep_service             频率点计划和记录
  calibration_service       标定和受限闭环

Adapters/
  board_ad9833              SPI/GPIO/MCLK
  board_ads8688             SPI/CONVST/IRQ/模式切换
  board_adc_dma             HAL ADC/DMA 回调
  board_dac_dma             HAL DAC/TIM/DMA

Library/
  pure DSP / protocol core  无固定 HAL、引脚和题目全局状态

Core/Drivers/
  CubeMX generated          时钟、引脚、DMA、IRQ
```

依赖只能向下。Library 不包含项目状态机，adapter 不进行题目分类，ISR 不执行大计算。

可复制的 L0 代码脚手架见 [`../../library/experimental/scaffolds/nonblocking_signal_workflow/README.md`](../../library/experimental/scaffolds/nonblocking_signal_workflow/README.md)。它提供状态、总超时、有限迭代、测量质量、故障和安全停机的最小实现；复制后必须改成题目专用服务，不能直接把通用 `float` 当作最终物理接口。

整题 BASIC/ADVANCED/回退/报告编排可从 [`../../library/experimental/scaffolds/contest_app/README.md`](../../library/experimental/scaffolds/contest_app/README.md) 建立。板级 HAL、DMA 和 IRQ 所有权按 [`../templates/board_adapter_contract_template.md`](../templates/board_adapter_contract_template.md) 冻结。

## 9. 非阻塞状态机契约

每个长操作服务尽量提供：

```c
Result Init(Context *ctx, const Config *cfg);
Result Start(Context *ctx, const Request *request);
Result Service(Context *ctx, uint32_t now_ms);
bool IsDone(const Context *ctx);
Result GetResult(const Context *ctx, Output *output);
Result Abort(Context *ctx);
```

每个状态必须定义：

- 进入动作；
- 持续服务；
- 成功条件；
- 超时；
- 硬件错误；
- 可重试次数；
- 退出时资源和安全状态。

## 10. 方案 A/B 和回退梯

每题至少形成：

| 层级 | 目标 |
|---|---|
| A 主方案 | 覆盖基础与发挥，自动化完整 |
| B 工程备选 | 器件或高风险算法失败时仍覆盖主要分值 |
| C 基础保底 | 固定参数、减少通道或人工步骤，在规则允许下完成基础 |
| D 调试模式 | 串口/示波器诊断，不计入正式自动流程 |

回退必须提前落实到代码模式和硬件跳线，不能在主方案失败后才临时设计。

## 12. 编码启动门

只有以下内容齐全，AI 才开始生成正式代码：

- [ ] 验收矩阵覆盖题目全部要求；
- [ ] 信号链和控制链完整；
- [ ] 四个硬约束和五类预算已计算；
- [ ] 主方案、备选和基础保底明确；
- [ ] 每个旧资产的沿用方法和不沿用参数已记录；
- [ ] CubeMX 外设、引脚、DMA、IRQ 由用户或当前工程事实确认；
- [ ] 文件分层、接口、数据所有权和回调所有权明确；
- [ ] 软件、板级和整题验证计划明确。

如果缺少 CubeMX 或硬件事实，AI 可以先实现纯算法、协议 fake-bus、状态机接口和测试，但不得猜测生成层或宣称完整工程可烧录。

## 13. 方案完成判据

方案架构完成必须产生：

1. 填写完整的方案模板；
2. 可追溯的 Knowledge/Library 映射；
3. 接口和状态机定义；
4. CubeMX 操作清单；
5. 代码文件清单和依赖方向；
6. 软件测试、板级冒烟、标定和整题验收矩阵；
7. 风险、未知项和回退方案。

代码完成还必须有对应构建、测试和硬件证据；“生成了源码”不是完成。
