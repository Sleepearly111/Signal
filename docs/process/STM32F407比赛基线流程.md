## 2. 已核对的固定配置

| 用途 | 当前配置 |
|---|---|
| MCU | STM32F407ZGT6 / LQFP144 |
| 时钟 | HSE 8 MHz，SYSCLK/HCLK 168 MHz |
| 工程 | CubeMX 6.17.0，STM32Cube FW_F4 V1.28.3，CMake |
| 调试串口 | USART2：PA2/PA3，115200 |
| 串口屏预留 | USART1：PA9/PA10，115200 |
| FPGA SPI | SPI3：PC10 SCLK、PC11 MISO、PC12 MOSI |
| FPGA 控制线 | PB0 `FPGA_CS_N`，上电高；PD6 `FPGA_DRDY`，上升沿 EXTI、下拉 |
| SPI 参数 | 主机、双线全双工、Mode 0、MSB first、软件片选、约 656.25 kbit/s |
| SPI3 RX DMA | DMA1 Stream0 / Channel0，Normal，byte，memory increment，Medium |
| SPI3 TX DMA | DMA1 Stream5 / Channel0，Normal，byte，memory increment，Medium |
| 中断优先级 | SPI3、DMA1 Stream0/5、EXTI9_5：抢占优先级 5，子优先级 0 |
| DAC 保留 | PA4 / DAC_OUT1，不因 FPGA 通信改动 |
| ADS8688 保留 | PD0～PD5 GPIO 软件 SPI |
| 内存设置 | Stack 0x1000，Heap 0x200 |

以上是 `.ioc` 和生成代码中的当前事实；它们仍需在实物板上逐项验证。

## 3. 新题建立顺序

1. 把 `stm32f4-template/` 完整复制到新的独立工程目录，不在基线目录直接写题目。
2. 删除复制品中的 `build/`，并把工程目录、`.ioc` 和 CMake 目标改为新题名称。
3. 用 CubeMX 打开复制后的 `.ioc`；若版本迁移，先备份并记录 CubeMX/FW 版本。
4. 保留 MCU、时钟、SWD、两个串口以及本题确定会用到的板级引脚。
5. FPGA 通信需要时保留 SPI3、PB0、PD6 和对应 DMA/NVIC；不用时可以关闭，但不要
   把 PA4 改成 SPI 片选。
6. 只删除确认不需要的外设；不冲突的板级预留可以保留。
7. 新增外设时逐项检查引脚、DMA Stream/Channel、IRQ 和回调所有权。
8. 重新生成后，先做 Debug/Release 最小构建，再接入 Adapter、Service 和 App。
9. 烧录后按 GPIO、串口、单外设、整条信号链的顺序验收。

不要把 2025G 的 `ui_basic.c`、题目状态机、算法参数或标定表复制进新工程。

## 7. 构建、烧录和最小验收

构建与烧录统一从 [`STM32烧录指南.md`](STM32烧录指南.md) 进入。烧录成功至少要看到
OpenOCD 的 `Programming Finished` 和 `Verified OK`，但这仍不能代替功能实测。

实物验收顺序：

1. 烧录、复位并确认程序进入主循环；
2. USART2 输出启动信息；
3. 普通 GPIO 和实体按键；
4. USART1 发送一条屏幕测试指令，但不接入 App 核心；
5. SPI3 单帧收发、CRC、超时和错误 ACK；
6. DRDY 连续包与 DMA 回调；
7. 最后连接信号发生器，验证完整测量链。

详细模板门状态见
[`../verification/stm32f4_template_gate.md`](../verification/stm32f4_template_gate.md)。
