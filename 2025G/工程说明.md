# 2025G 工程说明

2025 电赛 G 题 —— 电路模型探究装置（STM32F407）。本文件记录工程结构、编译烧录方法、
剩余待办，方便随时接手。

---

## 一、这是什么工程

- **目标 MCU**：STM32F407（底层按 F407ZGTx 生成，HAL 对整个 F407xx 通用）
- **信号链**：AD9833(DDS) → AD603(VGA,内部DAC1 CH1/PA4驱动) → AD8052(×5) → 输出；ADS8688(16bit ADC)测量
- **已实现**：基础部分 (2) Vpp≥3V 校准、(3) 1kHz→2Vpp、(4) 用户设定频率+电压
- 详细设计见 [DESIGN.md](DESIGN.md)

## 二、工程是自包含的

本工程已包含完整 CubeMX-CMake 结构，**不再依赖旁边的 test0**：

```
Core/            CubeMX 生成：外设初始化、main、中断、MSP（底层，重生时会重写）
Drivers/         HAL 库 + CMSIS（ST 官方，只读）
Middlewares/     CMSIS-DSP
cmake/           CubeMX 生成的构建片段（HAL/CMSIS 编译规则，别手改）
User/            复用驱动：AD9833、ADS8688（+ CALCULATE，本题未用）
Inc/ Src/        ← 本题应用逻辑（手写，见下）
app.ioc          CubeMX 配置源 —— 改外设用它打开
CMakeLists.txt   顶层构建：在 target_sources 挂 Src 应用代码
```

**应用代码分工**：
- `Src/dds_output.c` — AD9833 频率 + AD603 VGA(DAC)控制
- `Src/adc_measure.c` — ADS8688 采样 → RMS → Vpp
- `Src/transfer_calc.c` — H(s) 运行时计算
- `Src/ui_basic.c` — 串口屏(USART1) + 按键；含 printf 重定向 `_write`
- `Core/Src/main.c` — 主流程（RunBasic3/4、扫频校准、按键回调）写在 CubeMX 的
  `/* USER CODE */` 段里，CubeMX 重生不会覆盖
- `Src/main.c.orig` — 旧的独立 main，逻辑已并入 Core/main.c，**仅存档、不编译**

## 三、怎么编译

工具链是 VS Code 的 **STM32 扩展**自带的（ninja + arm-gcc + cmake，在
`AppData/Local/stm32cube/bundles/`）。

**VS Code 里**：Open Folder 打开 `2025G` → 选 preset **Debug** → 点 Build。

**命令行**（已验证可编过，产出 `build/Debug/app.elf`）：
```bash
B="$HOME/../20506/AppData/Local/stm32cube/bundles"   # 按实际用户名调整
export PATH="$B/gnu-tools-for-stm32/14.3.1+st.2/bin:$B/cmake/4.3.1+st.1/bin:$B/ninja/1.13.2+st.1/bin:$PATH"
cmake -S . -B build/Debug -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCMAKE_TOOLCHAIN_FILE=cmake/gcc-arm-none-eabi.cmake
cmake --build build/Debug
```

当前体积：Flash ~41KB / 1MB (4%)，RAM ~5KB / 128KB。

## 四、怎么烧录

- VS Code STM32 扩展的烧录/调试按钮（F5），或
- `STM32_Programmer_CLI`（在 bundles/programmer 里）下载 `build/Debug/app.elf`

## 五、改外设（CubeMX）

机器已装 **STM32CubeMX 独立版**。改外设：CubeMX 打开 `app.ioc` → 改 → **GENERATE CODE**
（Project Manager 的 Toolchain/IDE 保持 **CMake**）。重生只动底层，`Src/` 和 USER CODE 段不受影响。
DAC1 CH1(PA4) 已在本工程中启用。
