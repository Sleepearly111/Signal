# 2025G 发挥（2）AD630 FLL + 软件 DDS 调试总结

> 整理日期：2026-07-27  
> 工程：`projects/已完成项目/2025G/2025G/`  
> 验证边界：用户在当前板卡、接线和题目条件下确认发挥（2）完全正常，记为 L3 Hardware Tested。  
> 目标：只消除频差，不锁定绝对相位。

## 1. 最终信号链

```text
外部周期信号 → 未知电路 → 真实输出 ─────────────→ AD630 IN_B（隔直）
                         │
                         └→ 探究装置测量、建模与波形复现

STM32 PA5 DAC ← 1.2 MSPS DMA ← 32位软件DDS ← FLL频率微调
     │
     └──────────────────────────────────────→ AD630 IN_A（隔直）

AD630 OUT → ADS8688 CH2 → 拍频测量 → SEARCH/HOLD FLL
```

题目对相位无要求，因此最终方案没有PLL、Phase Acquisition或固定相位目标。

## 2. 最终实现

### 2.1 软件 DDS

- TIM6固定时钟：84 MHz；
- TIM6固定分频：70，`ARR=69`；
- DAC更新率：1.2 MSPS；
- DMA循环缓冲区：256点，HT/TC各补128点；
- 波形源表：256点任意周期波形；
- 相位累加器：32位；
- 频率分辨率：`1.2 MHz / 2^32 ≈ 0.00028 Hz`；
- FLL命令单位：0.1 Hz；
- ISR只做整数相位累加、查表和缓冲区写入，不打印、不做浮点谐波合成。

50 kHz时每周期约24个DAC采样点，满足题目波形复现；低频时采样点更多。

### 2.2 AD630拍频FLL

状态机：

```text
IDLE → SEARCH → CALIBRATE → HOLD
          ↑                    │
          └────── 失锁 ───────┘
```

SEARCH：

- 主循环连续请求ADS8688 CH2采样；
- 每100点统计一次，使用实际窗口耗时，不假定固定采样率；
- AD630输出相对慢变直流中心做带迟滞上升过零；
- 相邻完整过零周期换算为拍频；
- 只允许一个“新鲜拍频周期”触发一次控制，旧周期不得重复使用；
- 拍频大于0.5 Hz时使用0.5 Hz粗调；
- 拍频不大于0.5 Hz时使用0.1 Hz细调；
- 扰动后拍频明显变差才反向。

锁定与失锁：

- `beat < 0.18 Hz`，连续两个新拍频周期后进入HOLD；
- HOLD冻结SEARCH找到的DDS trim；
- 连续两个新拍频周期高于0.35 Hz后回到SEARCH；
- 没有新拍频周期时不重复调整。

### 2.3 波形复现

- FFT保留用于测频参考和正弦/矩形/三角波分类；
- 基波频率优先使用过零周期测量；
- 矩形波采用标准奇次谐波 `1/n`；
- 三角波采用交替反相的奇次谐波 `1/n²`；
- 每次谐波叠加学习到的未知电路幅频、相频响应；
- 所有标准波形谐波统一参考输入过零相位，避免非相干FFT bin破坏相对相位。

## 3. 重点调试记录

### 3.1 AD630输出不变化

现象：

- AD630输出近似固定；
- 强制±5 Hz频差时仍看不到对应拍频。

根因：

- 两路输入的隔直链路存在问题，AD630 A/B端没有得到正常交流正弦信号。

处理：

- 修复隔直电路；
- 分别在AD630 A、B输入端确认交流波形；
- 再观察AD630 OUT。

结论：

- 必须先验证A、B端真实交流输入，再判断AD630或软件；
- PA5带1.65 V直流偏置，不能省略隔直。

### 3.2 开环±5 Hz验证

目的：

- 分离执行器问题和FLL算法问题。

验证内容：

- `trim=0 → +5 → -5 → 0 Hz`；
- 示波器漂移方向在正负频差切换时反转；
- AD630拍频约等于强制频差；
- 执行器统计量随trim绝对值增加。

结果：

- AD630链路和频率执行方向得到确认；
-完成后移除开环测试，KEY1直接进入正式复现和FLL。

### 3.3 不同频率表现不一致

现象：

- 30、32、35 kHz较稳定；
- 31、33、34 kHz等频率漂移明显；
- 11、22 kHz出现跳变。

根因：

- 旧方案使用“整数波表长度 × TIM6整数分频”；
- 某些频率可被整数乘积精确表示，其他频率存在数Hz到数十Hz量化误差；
- ARR±1整周期调整还会产生离散相位跳变。

曾做的缓解：

- 启动trim补偿整数定时误差和约-40 ppm晶振误差；
- 调整波表长度/分频组合；
-修正sigma-delta恢复周期导致的平均频率公式错误。

最终处理：

- 放弃变ARR执行器；
- 改为固定1.2 MSPS、32位相位累加软件DDS。

### 3.4 波形偶发闪动或连续闪动

现象：

- 平均频率已经接近，但示波器偶尔突然跳一下或连续闪动；
- 40 kHz附近可见瞬时向一侧跳、整体又向另一侧漂。

根因：

- ARR±1会让一个完整波形周期突然变长或变短；
-平均频率正确不代表瞬时相位连续；
- 示波器触发会放大这种离散相位阶跃。

最终处理：

- 软件DDS只改变相位步进；
- TIM6始终保持`ARR=69`；
- 相位累加跨DMA半缓冲连续，不重启DAC。

硬件日志：

```text
[FLL_STAT] mode=DDS ... ARR=69 ... render_max≈40us
```

128点半缓冲时间约106.7 us，实测生成时间约40 us，具备充足余量。

### 3.5 40 kHz SEARCH方向来回反转

现象：

- 0.1 Hz调整时，拍频估计在约1.7～1.9 Hz波动；
- P&O把估计噪声误判为调整效果，方向反复变化。

处理：

- 拍频大于0.5 Hz时改用0.5 Hz粗调；
- 粗调反向裕量0.15 Hz；
- 细调反向裕量0.04 Hz；
- 只使用新测得的完整拍频周期。

### 3.6 矩形波复现形状错误

现象：

- 8 kHz矩形输入经过未知低通电路后，真实输出接近三角波；
- 探究装置复现输出却接近圆角矩形。

日志证据：

- 过零测频约7999.7 Hz；
- FFT参考频率约7588 Hz；
- 三次谐波/基波约0.336；
- DDS频率和缓冲生成时间正常。

根因：

- 1 MSPS、2048点FFT的bin间隔约488.3 Hz；
- 8 kHz不是相干bin；
- 单独读取各次谐波FFT bin相位，不能保持矩形波各奇次谐波的正确相对相位。

处理：

- FFT只负责波形分类；
- 标准波形改用解析傅里叶系数；
- 各谐波以过零相位为统一参考；
- 再施加未知电路模型的幅相响应。

结果：

- 用户确认矩形波复现正常。

## 4. 最终关键日志判读

正常DDS：

```text
[FLL_STAT] mode=DDS trim=...
phase_step=...
ARR=69
commanded=...
render_max=...us
```

判据：

- `ARR`必须始终为69；
- `render_max < 106.7 us`，当前实测约40 us；
- `commanded`随trim平滑变化；
- DAC启动计数不应在固定频率下持续增加。

正常SEARCH：

```text
[AD630_FLL] SEARCH ... beat=... fresh=1 search_dir=...
```

- `fresh=1`才允许使用本次拍频做控制；
- 大拍频阶段每次命令通常为±5，即±0.5 Hz；
- 小拍频阶段每次命令通常为±1，即±0.1 Hz。

正常HOLD：

```text
[AD630_FLL] HOLD_FLL ... trim=frozen
```

- HOLD允许任意固定相位；
- 极慢相位移动不等于FLL失败；
- 只有拍频重新超过失锁阈值才回SEARCH。

## 5. 验证结论

当前板卡和接线条件下，用户确认：

- 发挥（2）完全正常；
- 1～50 kHz范围频率稳定性满足使用；
- 正弦、矩形、三角波复现正常；
- 软件DDS消除了旧ARR调整导致的明显闪跳；
- AD630 FLL只锁频率，不引入PLL相位控制。
- 2026-07-27完成FLL遗留代码清理后重新烧录回归；
- 8 kHz矩形波和40 kHz频点均正常，整理版固件继续保持L3。

当前最高证据等级：L3 Hardware Tested。

该结论不自动传递到不同板卡、不同晶振、不同AD630增益/低通参数或不同ADS8688采样调度。复用时必须重新测量实际采样率、DDS时钟和拍频噪声。

## 6. 后续资产化边界

适合提取：

- 拍频周期测量器；
- P&O粗细两级FLL控制器；
- 32位相位步进接口；
- 锁定/失锁迟滞状态机；
- DMA半缓冲软件DDS内核。

不应直接进入纯Library：

- ADS8688 CH2手动读取；
- AD630具体电压换算和模拟接线；
- TIM6、DAC、DMA句柄及中断回调；
- -40 ppm板级启动补偿；
- 题目专用波形分类、未知电路模型和UI流程。
